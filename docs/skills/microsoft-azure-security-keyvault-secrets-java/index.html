Findings

MEDIUM Hardcoded Secrets in Code Examples Data Exfiltrationllm

The instruction body contains hardcoded sensitive credentials in code examples, including a database password ('P@ssw0rd123!') and an API key ('sk_live_abc123xyz'). While these appear to be example values for demonstration purposes, including literal secrets in documentation creates security risks: users may copy-paste these examples without changing credentials, developers may accidentally commit real secrets following this pattern, and it normalizes hardcoding secrets in code. Best practice is to use placeholder values like '<your-password-here>' or environment variable references.

SKILL.md

KeyVaultSecret secret = secretClient.setSecret("database-password", "P@ssw0rd123!");
...
KeyVaultSecret secretWithOptions = secretClient.setSecret(
    new KeyVaultSecret("api-key", "sk_live_abc123xyz")
Remediation: Replace all hardcoded credential values with placeholders (e.g., '<your-database-password>', '<your-api-key>') or references to environment variables. Add explicit warnings in documentation that example credentials must never be used in production. Consider using clearly fake formats like 'example_password_replace_me' to make it obvious these are not real credentials.
