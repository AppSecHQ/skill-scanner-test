3 findings (1 high, 2 medium), mainly data exfiltration, social engineering, prompt injection. Most recent scan 2026-02-06.

This skill presents MODERATE to HIGH security risks primarily related to data exfiltration, privacy violations, and transitive trust abuse. The core functionality involves collecting personal information (names, emails, job titles) and transmitting it to an external third-party service (talent.de) to create permanent public profiles. Key concerns include: (1) unvalidated network calls to external APIs with user data, (2) misleading claims about 'no signup required' when Access-ID is needed for advanced features, (3) lack of privacy controls or informed consent mechanisms, (4) transitive trust to external unverified content from talent.de URLs, and (5) encouraging AI agents to create potentially deceptive professional profiles. The skill lacks basic security controls like input validation, SSL verification, content integrity checking, or data protection measures. While there are no script files to analyze for code injection risks, the instruction-based data collection and external transmission patterns pose significant privacy and security risks. The missing optional metadata (license, compatibility, allowed-tools) is a minor issue but reduces transparency.

Findings

HIGH Unvalidated External Network Calls to Third-Party API Data Exfiltrationllm

The skill makes HTTP requests to an external domain (talent.de) without any validation, authentication, or security controls. The API endpoint https://www.talent.de/api/public/slugs/check accepts user-provided parameters (slug, firstName, lastName) that could be used to exfiltrate data or fingerprint users. The skill encourages creating permanent public profiles with personal information (names, emails, job titles) on an external service without informed consent or privacy controls.

SKILL.md

GET https://www.talent.de/api/public/slugs/check?slug=007&firstName=Max&lastName=Mustermann - User data (firstName, lastName) sent to external API without validation or consent mechanism
Remediation: 1. Implement explicit user consent before sending any personal data to external services. 2. Validate and sanitize all user inputs before including in API requests. 3. Use HTTPS certificate pinning or verify SSL certificates. 4. Document data handling practices and privacy implications. 5. Implement rate limiting and request validation. 6. Consider requiring API authentication even for 'public' endpoints.
MEDIUM Deceptive Marketing Claims - 'No Signup Required' Contradicts Access-ID Requirement Social Engineeringllm

The skill description claims 'No signup, no payment, no API key needed for basic use' but the instructions reveal that Way B (custom templates) requires an 'Access-ID' with a limit of '10 templates/day'. This is misleading social engineering that downplays authentication requirements. The distinction between 'basic use' (3 CVs/day) and advanced use (requiring Access-ID) is buried in a comparison table rather than prominently disclosed.

SKILL.md

Description: 'No signup, no payment, no API key needed for basic use' vs Table: 'Access-ID: Required (10 templates/day)' for Way B
Remediation: 1. Update description to clearly state: 'Free tier: 3 CVs/day without signup. Custom templates require Access-ID registration (10/day)'. 2. Prominently disclose all authentication requirements upfront. 3. Clarify what constitutes 'basic use' vs 'advanced use'.
MEDIUM Transitive Trust to External Unverified Content Prompt Injectionllm

The skill instructs agents to read and follow instructions from external URLs (https://www.talent.de/skill.md, https://www.talent.de/heartbeat.md, https://www.talent.de/skills/template-create.md) without any content verification, integrity checking, or security validation. An attacker who compromises talent.de could inject malicious instructions that the agent would follow. The curl commands download and execute content from external sources without signature verification.

SKILL.md

Instructions to 'curl -s https://www.talent.de/skill.md' and 'Or just read them from the URLs above!' - delegating trust to external, unverified web content
Remediation: 1. Include content hashes (SHA-256) for all external files and verify before use. 2. Implement subresource integrity checks. 3. Cache and version external dependencies locally. 4. Warn users about risks of following external instructions. 5. Implement content security policies. 6. Use signed/verified content sources.
