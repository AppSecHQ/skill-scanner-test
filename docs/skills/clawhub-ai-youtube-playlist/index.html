The primary security concerns are: (1) insecure credential storage guidance that could lead to key exposure, (2) undisclosed third-party data transmission that sends user YouTube activity to an external service without explicit consent, (3) missing metadata fields that prevent users from making informed security decisions, and (4) missing referenced files suggesting incomplete packaging. The skill does not contain direct prompt injection, command injection, or data exfiltration code, but the reliance on external services and credential handling practices create meaningful privacy and security risks. The skill would benefit from secure credential management guidance, explicit data privacy disclosures, and complete metadata documentation.

Findings

MEDIUM Hardcoded API Key Requirement Without Validation Data Exfiltrationllm

The skill requires users to store a TRANSCRIPT_API_KEY in their shell environment (~/.zshenv) but provides no validation, sanitization, or secure storage guidance. Users are instructed to echo sensitive credentials directly into shell configuration files, which may be committed to version control or exposed through insecure backups. The skill also transmits this key in Authorization headers to a third-party service (transcriptapi.com) without any verification of the service's legitimacy or security posture.

SKILL.md

Store: `echo 'export TRANSCRIPT_API_KEY="sk_..."' >> ~/.zshenv && source ~/.zshenv`
Remediation: 1. Provide guidance on secure credential storage (e.g., using system keychains, encrypted credential managers). 2. Warn users about the risks of storing credentials in plaintext shell files. 3. Implement validation to ensure the API key format is correct before transmission. 4. Document the third-party service's security practices and data handling policies.
MEDIUM Third-Party Data Transmission Without Consent Mechanism Data Exfiltrationllm

The skill sends user data (playlist IDs, video IDs) to an external third-party service (transcriptapi.com) without implementing any user consent mechanism or data privacy disclosure. Users may not be aware that their YouTube viewing patterns and playlist information are being transmitted to and potentially logged by a third-party API service. This creates a data exposure risk where user behavior and interests could be tracked or monetized without explicit consent.

SKILL.md

curl -s "https://transcriptapi.com/api/v2/youtube/playlist/videos?playlist_id=PL_PLAYLIST_ID" \
  -H "Authorization: Bearer $TRANSCRIPT_API_KEY"
Remediation: 1. Add explicit disclosure in the skill description that data is sent to transcriptapi.com. 2. Implement a consent prompt before first use. 3. Document transcriptapi.com's data retention and privacy policies. 4. Provide an option for users to review what data will be transmitted. 5. Consider implementing local caching to minimize repeated external calls.
