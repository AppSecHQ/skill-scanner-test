Findings

HIGH Unauthorized Skill Orchestration and Control Without Implementation Unauthorized Tool Usellm

The skill claims to act as a 'central brain' that manages, coordinates, discovers, schedules, monitors, restarts, and controls all other installed skills. This represents tool exploitation through skill orchestration capabilities that could enable unauthorized control over other skills' execution, configuration, and behavior. However, no implementation code is provided, making it impossible to verify safety controls or validate the claimed functionality.

SKILL.md

Description claims: 'acts as the central brain for OpenClaw, intelligently managing all installed skills', 'discovers available skills, resolves dependencies, and schedules actions', 'detect failures, restart stuck skills', 'unifying configuration, secrets management, and event handling'. No Python or Bash scripts provided to implement these capabilities.
Remediation: 1. Provide complete implementation code for all orchestration capabilities. 2. Implement strict access controls and permission checks before managing other skills. 3. Require explicit user confirmation before restarting or modifying other skills. 4. Document all skill interaction mechanisms and security boundaries. 5. Implement audit logging for all orchestration actions. 6. Add sandboxing to prevent unauthorized access to other skills' data or configuration.
HIGH Centralized Secrets Management Without Security Controls Data Exfiltrationllm

The skill claims to provide 'centralized secrets management' across all skills, which would require access to sensitive credentials, API keys, and authentication tokens. Without implementation code or security controls visible, this represents a significant data exposure risk. A compromised or malicious orchestration skill with access to all secrets could exfiltrate credentials for all installed skills.

SKILL.md

Claims 'unifying configuration, secrets management' across all skills. No code provided showing how secrets are stored, encrypted, accessed, or protected. No evidence of encryption, access controls, or secure storage mechanisms.
Remediation: 1. Implement encrypted secrets storage using industry-standard encryption (e.g., AES-256). 2. Use secure key derivation and never store secrets in plaintext. 3. Implement principle of least privilege - skills should only access their own secrets. 4. Provide audit logging for all secrets access. 5. Use OS-level secure storage (keychain/credential manager) where available. 6. Document the secrets management architecture and threat model.
