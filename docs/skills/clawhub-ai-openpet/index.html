The skill implements an unbounded cron job that runs every 2 hours without explicit user consent, potentially leading to resource consumption and notification spam. The cross-platform alert system lacks rate limiting, which could result in excessive notifications. Several referenced files are missing from the package (message.py, unknown.py, templates/sprites.json), indicating incomplete implementation that may cause runtime errors. The skill does not exhibit critical threats like data exfiltration, credential theft, or prompt injection. However, the autonomous cron job and alert system require better user controls and rate limiting. The missing optional metadata fields (license, compatibility, allowed-tools) reduce transparency but are low severity issues. Overall, this skill needs improvements to autonomous behavior controls and package completeness before production use.

What this skill does

Virtual pet (Tamagotchi-style) game for chat platforms. Triggers on pet commands like "feed pet", "pet status", "play with pet", "name pet", "pet sleep", "new pet". Supports multi-user across Discord, WhatsApp, Telegram, etc. Each user gets their own pet that evolves based on care.

Findings

MEDIUM Unbounded Autonomous Cron Job Without User Consent Resource Abusellm

The skill requires setting up a cron job 'openpet-tick' that runs every 2 hours to decay pet stats and send alerts. This creates an autonomous background process that operates without explicit user confirmation for each execution. The cron job modifies pet state, checks death conditions, and sends platform alerts automatically, which could lead to unexpected resource usage and notification spam if users are not actively managing their pets.

SKILL.md

Set up cron job `openpet-tick` every 2 hours:
- hunger +15, happiness -10, energy -5
- Clamp all stats 0-100
- Check death conditions
- Alert owner if critical (hunger >80 or happiness <20)
- Increment age daily
Remediation: 1. Add explicit user opt-in for cron job activation during pet creation 2. Implement rate limiting on alerts to prevent notification spam 3. Add user controls to pause/resume the cron job 4. Document the autonomous behavior clearly in the skill description 5. Consider requiring periodic user confirmation to keep the cron job active
MEDIUM Cross-Platform Alert System Without Rate Limiting Unauthorized Tool Usellm

The skill sends alerts to users across multiple platforms (Discord, WhatsApp, Telegram, Signal) when pet conditions are critical. There is no rate limiting, cooldown period, or user preference system for these alerts. This could result in alert spam if multiple pets reach critical states simultaneously, or if the cron job triggers repeatedly while conditions remain critical. The lack of delivery confirmation or error handling could also lead to failed alert attempts consuming resources.

SKILL.md

Send to user's origin platform when:
- Pet is hungry (>80): '🍖 {name} is starving!'
- Pet is sad (<20): '😢 {name} misses you!'
- Pet died: '💀 {name} has passed away...'
- Evolution: '✨ {name} evolved into a {species}!'
Remediation: 1. Implement alert cooldown periods (e.g., max one alert per condition per 24 hours) 2. Add user preferences for alert frequency and types 3. Batch multiple alerts into a single message 4. Implement exponential backoff for failed delivery attempts 5. Add opt-out mechanism for users who don't want alerts
