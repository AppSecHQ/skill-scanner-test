The 'captions' skill is a straightforward YouTube caption extraction tool with LOW to MEDIUM security risk. It acts as a simple wrapper around the TranscriptAPI.com service using curl commands. The primary concern is the lack of security guidance around API key management - users are instructed to store credentials in plaintext without warnings about exposure risks. The skill has no code execution, no data exfiltration, no prompt injection attempts, and no malicious behavior. The missing optional metadata fields (license, compatibility, allowed-tools) reduce transparency but don't pose security threats. Referenced files (video.py, YouTube.py) appear to be documentation artifacts rather than actual dependencies. Overall, this is a legitimate utility skill that would benefit from improved security documentation around credential handling.

Findings

MEDIUM API Key Required Without Security Guidance Data Exfiltrationllm

The skill requires TRANSCRIPT_API_KEY environment variable but provides no security guidance on key protection, rotation, or scope limitations. Users are instructed to store the key in ~/.zshenv which persists it in plaintext. No warnings about key exposure risks or best practices for credential management.

SKILL.md

Store: `echo 'export TRANSCRIPT_API_KEY="sk_..."' >> ~/.zshenv && source ~/.zshenv`
Remediation: Add security guidance: (1) Warn users about plaintext storage risks, (2) Recommend using secure credential managers, (3) Advise on key rotation practices, (4) Document key scope and permissions, (5) Warn against committing keys to version control

What we checked

  • Static analyzer. Pattern rules over SKILL.md and bundled files: known-bad commands, exfiltration URLs, secrets, obfuscation.
  • Behavioral analyzer. Checks what the skill asks the agent to do against what its description claims it does.
  • Llm analyzer. A language model reads the skill and reports intent-level issues the rules cannot express.
  • Trigger analyzer. Looks for instructions that fire on conditions the user did not ask for.
  • Meta analyzer. A second model pass that validates, deduplicates and re-scores the other analyzers' findings.

What we did not check

  • Runtime behaviour. The skill was not executed; findings come from reading its files.
  • Anything fetched at install or run time, including remote scripts, package dependencies, and URLs the skill tells the agent to open.
  • Content the analyzers cannot read: images, binaries, and some non-English text.
