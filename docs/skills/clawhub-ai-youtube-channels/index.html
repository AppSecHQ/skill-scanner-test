Findings

MEDIUM Hardcoded API Key Exposure Risk in Setup Instructions Data Exfiltrationllm

The SKILL.md instructions guide users to store their TRANSCRIPT_API_KEY in ~/.zshenv using echo append, which could lead to accidental exposure or misconfiguration. While the skill itself doesn't contain hardcoded secrets, the setup pattern encourages storing sensitive credentials in shell configuration files that may be inadvertently committed to version control or exposed through other means. The instructions also demonstrate the API key in curl commands, which could lead to shell history exposure.

SKILL.md

Store: `echo 'export TRANSCRIPT_API_KEY="sk_..."' >> ~/.zshenv && source ~/.zshenv`
Auth: `-H "Authorization: Bearer $TRANSCRIPT_API_KEY"`
Remediation: Recommend using more secure credential storage methods such as: (1) dedicated credential managers (e.g., pass, 1Password CLI), (2) encrypted environment variable stores, (3) warning users about shell history exposure when using API keys in curl commands, (4) suggesting .env files with proper .gitignore configuration instead of shell config files.
