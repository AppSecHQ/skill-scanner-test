The primary security concerns are around credential management (API key storage in shell config without security guidance) and data privacy (sending video URLs to third-party service without user consent or disclosure). However, it lacks important security best practices around credential handling and privacy transparency. The missing metadata fields and referenced file are minor documentation issues. Overall risk level is MODERATE - the skill is functional and non-malicious, but needs security and privacy improvements.

Findings

MEDIUM Hardcoded API Key Requirement Without Validation Data Exfiltrationllm

The skill requires users to store a TRANSCRIPT_API_KEY in their shell environment (~/.zshenv) but provides no validation, sanitization, or security guidance. Users are instructed to echo their API key directly into shell configuration files, which could expose credentials if the file has incorrect permissions or is accidentally committed to version control.

SKILL.md

Store: `echo 'export TRANSCRIPT_API_KEY="sk_..."' >> ~/.zshenv && source ~/.zshenv`
Remediation: Provide security guidance: (1) Verify file permissions (chmod 600 ~/.zshenv), (2) Warn against committing credentials to git, (3) Suggest using a secrets manager or encrypted credential store, (4) Add validation to check if the key format is correct before making API calls.
MEDIUM External API Data Transmission Without User Consent Data Exfiltrationllm

The skill sends user-provided video URLs to an external third-party API (transcriptapi.com) without explicit user consent or privacy disclosure. Video URLs may contain sensitive information (unlisted videos, private shares, user viewing history). The skill does not disclose what data TranscriptAPI.com collects, logs, or retains.

SKILL.md

curl -s "https://transcriptapi.com/api/v2/youtube/transcript?video_url=VIDEO_URL..." -H "Authorization: Bearer $TRANSCRIPT_API_KEY"
Remediation: Add privacy disclosure: (1) Inform users that video URLs are sent to transcriptapi.com, (2) Link to TranscriptAPI's privacy policy, (3) Warn about sharing unlisted/private video URLs, (4) Consider adding a confirmation prompt before sending data to external services.
