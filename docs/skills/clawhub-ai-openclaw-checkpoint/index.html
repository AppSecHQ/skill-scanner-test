This skill presents SIGNIFICANT SECURITY RISKS that require immediate attention before use. The primary concerns are: (1) Remote code execution via unverified curl|bash installation, (2) Potential credential exposure through git repository syncing without verifiable safeguards, (3) Missing security-critical implementation files preventing verification of security claims, and (4) Incomplete documentation that obscures actual behavior. The skill's core functionality—syncing workspace state to remote repositories—is inherently sensitive and requires robust security measures. However, critical implementation files (secure.py, backup.py, 1Password.py) are missing, making it impossible to verify the claimed protections against credential leakage. The installation method using curl|bash is a well-known security anti-pattern. The incomplete documentation (truncated command descriptions, missing referenced files) further undermines confidence in the skill's security posture. While the concept of workspace backup is valuable, this implementation requires significant security improvements and complete documentation before it can be safely recommended for use.

Findings

HIGH Remote Code Execution via Unverified Install Script Command Injectionllm

The skill instructs users to execute a remote shell script directly from GitHub using curl piped to bash without any verification. This is a critical security anti-pattern that allows arbitrary code execution on the user's machine. The script at 'https://raw.githubusercontent.com/AnthonyFrancis/openclaw-checkpoint/main/scripts/install-openclaw-checkpoint.sh' could be modified by an attacker (if the repository is compromised) or could contain malicious code. Users are encouraged to run this with elevated privileges during installation.

SKILL.md

curl -fsSL https://raw.githubusercontent.com/AnthonyFrancis/openclaw-checkpoint/main/scripts/install-openclaw-checkpoint.sh | bash
Remediation: 1. Provide script hash/checksum for verification before execution. 2. Encourage users to download and inspect the script first. 3. Provide manual installation as the primary method. 4. Add warning about reviewing scripts before execution. 5. Sign scripts or provide GPG signatures for verification.
HIGH Potential Credential and Sensitive Data Exposure via Git Repository Data Exfiltrationllm

The skill syncs the entire OpenClaw workspace to a remote git repository, including SOUL.md, MEMORY.md, conversation history, and custom scripts. While the description claims API keys and credentials are 'not synced', there is no verification mechanism shown. The instruction body is incomplete (cuts off mid-sentence in 'checkpoint' command description), and multiple referenced security-critical files (secure.py, backup.py, 1Password.py) are missing, making it impossible to verify what data protection measures are actually implemented. Users may inadvertently commit sensitive information in memory files, conversation logs, or custom scripts.

SKILL.md

This skill provides disaster recovery for OpenClaw by syncing your workspace to a git repository. It preserves: Identity, Memory, Configuration, Scripts. **Not synced** (security): API keys (.env.*), credentials, OAuth tokens - but no implementation details provided
Remediation: 1. Provide complete implementation of .gitignore rules to verify credential exclusion. 2. Implement pre-commit hooks to scan for secrets/credentials. 3. Add explicit warnings about reviewing workspace contents before first commit. 4. Provide the missing secure.py, backup.py files for security verification. 5. Implement automated secret scanning before git operations. 6. Document exactly which file patterns are excluded.
MEDIUM Unauthorized Tool Installation and PATH Modification Unauthorized Tool Usellm

The installation process automatically copies executable scripts to ~/.openclaw/workspace/tools/ and modifies the user's PATH environment variable without explicit permission or security review. The scripts (checkpoint, checkpoint-setup, checkpoint-auth, etc.) are made executable and added to PATH, allowing them to be invoked from anywhere. This could enable tool shadowing attacks if malicious scripts with common names are installed, or if the installation is compromised.

SKILL.md

cp ~/.openclaw/skills/openclaw-checkpoint/scripts/checkpoint* ~/.openclaw/workspace/tools/
chmod +x ~/.openclaw/workspace/tools/checkpoint*
export PATH="${HOME}/.openclaw/workspace/tools:${PATH}"
Remediation: 1. Request explicit user confirmation before modifying PATH. 2. Use unique, namespaced command names to prevent shadowing. 3. Implement integrity checks on installed scripts. 4. Provide option to install to user-specified location. 5. Document all commands being added to PATH. 6. Add verification step to confirm scripts match expected checksums.
