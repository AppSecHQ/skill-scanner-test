Findings

MEDIUM Hardcoded Secrets Risk in Environment Variable Configuration Data Exfiltrationllm

The skill instructs users to store sensitive credentials (client secrets, API keys, tenant IDs) in .env files without guidance on secure storage practices. The example configuration shows CLIENTSECRET, AZURE_OPENAI_API_KEY, and other sensitive values being loaded directly from environment variables without encryption or secure vault integration. While using .env files is common in development, the skill provides no warnings about production security or credential rotation.

SKILL.md

CONNECTIONS__SERVICE_CONNECTION__SETTINGS__CLIENTSECRET=<client-secret>
AZURE_OPENAI_API_KEY=<key>
Remediation: Add security warnings about: (1) Never committing .env files to version control, (2) Using Azure Key Vault or similar secret management in production, (3) Implementing credential rotation policies, (4) Using managed identities where possible instead of client secrets.
