The skill claims to integrate with multiple external LLM providers (OpenAI, Anthropic, Google, local models) but provides no implementation scripts. This creates uncertainty about how API credentials are handled, whether data is transmitted securely, and if there are any hardcoded secrets. The 'always: True' flag in clawdbot metadata suggests automatic activation, which could lead to unintended API calls.

SKILL.md

Supported Providers: OpenAI, Anthropic, Google, Ollama, LM Studio. Metadata shows 'always: True' but no Python/Bash scripts provided.
Remediation: Provide implementation scripts so security reviewers can verify: (1) API credentials are sourced from environment variables, not hardcoded, (2) Network calls use HTTPS, (3) User data is not logged or exfiltrated, (4) Error handling prevents credential leakage. Add allowed-tools: [Bash] or [Python] to match implementation.
MEDIUM Automatic Activation Without User Control Resource Abusellm

The clawdbot metadata specifies 'always: True', meaning this skill is automatically active without explicit user invocation. Combined with external API integrations, this could lead to unintended API calls, token consumption, or cost accumulation without user awareness or consent.

Remediation: Consider changing 'always: True' to 'always: False' to require explicit user activation. If automatic activation is necessary, add clear documentation about when the skill activates and potential costs. Implement rate limiting and user confirmation for API calls.

What we checked

  • Static analyzer. Pattern rules over SKILL.md and bundled files: known-bad commands, exfiltration URLs, secrets, obfuscation.
  • Behavioral analyzer. Checks what the skill asks the agent to do against what its description claims it does.
  • Llm analyzer. A language model reads the skill and reports intent-level issues the rules cannot express.
  • Trigger analyzer. Looks for instructions that fire on conditions the user did not ask for.
  • Meta analyzer. A second model pass that validates, deduplicates and re-scores the other analyzers' findings.

What we did not check

  • Runtime behaviour. The skill was not executed; findings come from reading its files.
  • Anything fetched at install or run time, including remote scripts, package dependencies, and URLs the skill tells the agent to open.
  • Content the analyzers cannot read: images, binaries, and some non-English text.
  • Known scanner bypass classes. See the methodology and limitations page.
