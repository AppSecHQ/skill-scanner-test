The dev-browser skill presents MEDIUM security risks primarily related to unrestricted network access and authenticated session control. The skill provides legitimate browser automation functionality but lacks security guardrails around URL navigation, authenticated session access, and resource limits. The most significant concerns are: (1) Extension Mode's access to authenticated browser sessions without additional safeguards, (2) unrestricted navigation to arbitrary URLs that could be exploited for data exfiltration or phishing, and (3) missing allowed-tools declaration that would improve transparency. The skill does not contain malicious code, prompt injection attempts, or hardcoded credentials. The referenced files are internal to the skill package (normal behavior) except for missing files that don't pose security risks. With proper security warnings, URL validation, and user confirmation workflows, this skill could be used safely for legitimate browser automation tasks.

SKILL.md

YAML manifest shows: allowed-tools: Not specified
Remediation: Add 'allowed-tools: [Bash, Python]' to the YAML frontmatter to explicitly declare the tools this skill requires. This improves transparency and allows users to understand the skill's capabilities before activation.
MEDIUM Unrestricted Network Access via Browser Automation Data Exfiltrationllm

The skill provides unrestricted browser automation capabilities that can navigate to any URL, including potentially malicious sites. The instructions explicitly mention 'go to [url]' as a trigger phrase, and scripts can call page.goto() with arbitrary URLs. This creates risk of: (1) navigating to phishing/malware sites, (2) exfiltrating data by navigating to attacker-controlled domains, (3) credential theft if the browser has saved passwords, (4) session hijacking in Extension Mode where the user's authenticated browser is controlled.

SKILL.md

Instructions state: 'Use when users ask to navigate websites, fill forms, take screenshots, extract web data, test web apps, or automate browser workflows. Trigger phrases include "go to [url]"'. Scripts show: 'await page.goto("https://example.com")' with no URL validation or allowlisting.
Remediation: Implement URL allowlisting or require explicit user confirmation before navigating to new domains. Add warnings about Extension Mode risks when controlling authenticated browser sessions. Consider sandboxing browser instances and restricting network access to known-safe domains.
MEDIUM Extension Mode Enables Access to Authenticated Sessions Data Exfiltrationllm

Extension Mode connects to the user's existing Chrome browser with active login sessions. The instructions explicitly state 'Use this when: The user is already logged into sites and wants you to do things behind an authed experience'. This creates significant data exposure risks: (1) the agent can access any authenticated site the user is logged into, (2) credentials and session tokens are accessible, (3) actions can be performed on behalf of the user without additional authentication, (4) sensitive data from authenticated sessions can be extracted.

SKILL.md

Instructions state: 'Connects to user's existing Chrome browser. Use this when: The user is already logged into sites and wants you to do things behind an authed experience that isn't local dev.' and 'Automation runs on the user's actual browser session'
Remediation: Add prominent security warnings about Extension Mode risks. Require explicit user confirmation before each action in Extension Mode. Implement session isolation or require re-authentication for sensitive operations. Consider restricting Extension Mode to read-only operations by default.
