Findings

MEDIUM SQL Injection Risk - Unvalidated User Input in Query Examples Command Injectionllm

The skill provides extensive SQL query examples and templates without any guidance on parameterized queries or input validation. The instruction body shows direct string concatenation patterns in SQL queries without warning about SQL injection risks. While the skill itself doesn't execute queries, it teaches unsafe SQL practices that could lead to SQL injection vulnerabilities when users implement the suggested patterns.

SKILL.md

Examples show direct value insertion like "WHERE status = 'active'" without discussing parameterized queries or prepared statements. No mention of SQL injection prevention, input sanitization, or use of parameterized queries throughout the extensive documentation.
Remediation: Add a dedicated security section covering: (1) Always use parameterized queries/prepared statements, (2) Never concatenate user input directly into SQL strings, (3) Include examples of safe query patterns using placeholders (?, :param, etc.), (4) Warn about SQL injection risks when constructing dynamic queries.
