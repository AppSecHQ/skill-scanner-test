The Vestaboard skill presents MEDIUM security risk primarily due to external API communication with user-provided credentials and missing implementation verification. The skill's stated purpose (controlling a Vestaboard display via cloud API) is legitimate, but several security concerns exist: (1) API tokens are required via environment variables without validation guidance, (2) network communication to third-party API cannot be verified as properly restricted, (3) missing input validation and rate limiting could enable abuse, (4) file path handling lacks documented validation, and (5) critical implementation files are missing, preventing code-level security verification. The skill would benefit from: explicit input validation, rate limiting, endpoint restriction verification, path traversal protection, and inclusion of all referenced implementation files. The missing metadata fields (license, compatibility, allowed-tools) reduce transparency but are lower severity. No evidence of prompt injection, command injection, or deliberate data exfiltration was found in the provided documentation.

MEDIUM Hardcoded API Token Environment Variable Names Data Exfiltrationllm

The skill requires API tokens via environment variables (VESTABOARD_TOKEN or VESTABOARD_RW_KEY) but provides no validation, sanitization, or secure handling guidance. While using environment variables is better than hardcoding secrets, the skill does not verify token format, implement rate limiting, or provide guidance on token rotation. The legacy fallback (VESTABOARD_RW_KEY) suggests potential use of deprecated authentication methods that may have weaker security properties.

SKILL.md

- Preferred: `VESTABOARD_TOKEN`
- Optional legacy fallback: `VESTABOARD_RW_KEY`
Remediation: 1. Document token format requirements and validation steps 2. Implement token validation before API calls 3. Add guidance on secure token storage and rotation 4. Deprecate legacy RW_KEY with migration timeline 5. Consider implementing token expiration checks
