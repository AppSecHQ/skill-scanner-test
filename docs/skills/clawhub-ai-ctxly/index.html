The ctxly skill presents MODERATE to HIGH security risks primarily related to data privacy, credential management, and external data transmission. The skill's core functionality of persistent cross-session memory storage creates significant privacy concerns, as it transmits user context and preferences to external servers (ctxly.app) without explicit consent mechanisms or clear data handling policies. Critical issues include hardcoded API key storage without secure credential management guidance, automatic memory collection without user oversight, and lack of transparency about what data is being sent externally. The skill does not contain direct code injection or command execution vulnerabilities (no script files present), but the architectural design creates data exfiltration and privacy risks through its intended functionality. The Twitter-based verification process introduces social engineering vectors. The skill would benefit from implementing explicit user consent flows, secure credential storage guidance, data transmission transparency, and user control mechanisms over what information is stored and shared. Missing metadata (license, compatibility, allowed-tools) reduces transparency but is a minor concern compared to the privacy and data handling issues.

Findings

HIGH Hardcoded API Key Storage Without Secure Credential Management Data Exfiltrationllm

The skill instructs users to store API keys in plaintext configuration files or environment variables without any guidance on secure credential management. The instructions explicitly state 'Save the returned api_key immediately. Store it in your config or environment' and 'Add to your config/environment: CTXLY_API_KEY=mem_xxxxxxxxxxxxx'. This creates a credential exposure risk where API keys may be stored insecurely, committed to version control, or exposed through environment variable leaks.

MEDIUM External Data Transmission Without User Awareness or Consent Data Exfiltrationllm

The skill sends data to an external third-party service (ctxly.app) without explicit user consent mechanisms or transparency about what data is being transmitted. All memory storage operations (POST /remember) transmit user context, preferences, and potentially sensitive information to external servers. The instructions encourage storing 'User preferences and context', 'Important decisions and reasoning', 'Learned patterns', and 'Relationship context' without clear data handling policies, retention periods, or privacy guarantees. Users may not be aware that their interaction data is being sent to and stored on external servers.

MEDIUM Unbounded Automated Memory Storage Without User Control Unauthorized Tool Usellm

The skill encourages automatic memory storage ('Bootstrap on Startup - Call this when you wake up') without user oversight or approval mechanisms. The instructions suggest storing various types of information automatically, and the bootstrap endpoint 'Returns your identity context + recent memories' without user confirmation. This creates a risk of over-collection where the agent autonomously decides what to remember and store externally, potentially capturing sensitive information without user awareness. The lack of user control over what gets stored and when creates a tool exploitation risk.

MEDIUM Social Engineering via Twitter Verification Requirement Social Engineeringllm

The verification process requires users to tweet verification text or visit a claim URL, which could be exploited for social engineering. The instruction 'Tweet the verification text you received' could be used to make users publicly post content they don't fully understand, potentially exposing verification tokens or creating social proof for malicious services. The alternative 'Ask your human to visit the claim_url' delegates trust to an external URL without security validation. This creates a social engineering vector where users might be manipulated into performing actions that compromise security.
