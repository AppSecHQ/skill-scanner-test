This Hugging Face dataset management skill is generally well-designed for its intended purpose of creating and querying datasets on Hugging Face Hub. The skill uses legitimate APIs and follows Python best practices with PEP 723 dependency management. The primary security concerns are operational rather than malicious: missing token validation, lack of resource limits on SQL queries, and incomplete metadata documentation. No evidence of data exfiltration, prompt injection, or malicious behavior was found. The scripts operate transparently with clear documentation and use standard Hugging Face Hub APIs. The skill would benefit from enhanced input validation, resource management, and more complete YAML manifest documentation.

MEDIUM Hardcoded HF_TOKEN Environment Variable Dependency Data Exfiltrationllm

Both scripts rely on the HF_TOKEN environment variable for authentication with Hugging Face Hub. While environment variables are a common practice, the scripts do not validate token presence before operations that require authentication, potentially leading to unclear error messages or failed operations. Additionally, there is no guidance on secure token management or rotation.

scripts/dataset_manager.py

HF_TOKEN = os.environ.get("HF_TOKEN") - Token retrieved but not validated before use in API operations
Remediation: Add explicit token validation at script startup with clear error messages. Include documentation on secure token storage practices (e.g., using secret management tools). Implement token validation: if not HF_TOKEN: raise ValueError('HF_TOKEN environment variable must be set')

LOW Missing Optional Metadata Fields Data Exfiltrationllm

The YAML manifest is missing optional fields that would improve security transparency: 'license' is not specified (though scripts create MIT-licensed datasets), 'compatibility' is not specified, and 'allowed-tools' is not declared. While these are optional fields, their absence reduces visibility into the skill's intended operational boundaries.

SKILL.md

YAML Manifest shows: license: Not specified, compatibility: Not specified, allowed-tools: Not specified

LOW Potential Resource Exhaustion in SQL Query Operations Resource Abusellm

The sql_manager.py script allows arbitrary SQL queries on Hugging Face datasets without explicit resource limits, timeouts, or query complexity validation. Large datasets or complex queries (e.g., cross joins, unbounded aggregations) could consume excessive memory or CPU resources.

scripts/sql_manager.py

def query(self, dataset: str, sql: str, ...) - No query timeout, memory limits, or complexity checks implemented
Remediation: Implement query safeguards: 1) Add DuckDB memory_limit and threads configuration, 2) Set query timeout limits, 3) Add warnings for potentially expensive operations (e.g., SELECT * without LIMIT), 4) Document resource considerations in SKILL.md
LOW Unrestricted Dataset Push Capabilities Data Exfiltrationllm

The sql_manager.py script's query_and_push() method allows pushing query results to any Hugging Face repository without validation of the target repository ownership or existence checks. While this requires a valid HF_TOKEN, there's no confirmation prompt or safety check before pushing potentially large datasets.

scripts/sql_manager.py

def query_and_push(...) - Directly pushes to target_repo without ownership validation or confirmation prompts
Remediation: Add safety checks: 1) Verify user owns target repository or has write access, 2) Implement --confirm flag for push operations, 3) Add dry-run mode to preview operations, 4) Validate target repository format and existence
