The ClawKey skill is a security-focused identity verification system with MODERATE security concerns. The skill's core purpose (verifiable human ownership via palm verification) is legitimate, but the implementation guidance has several gaps. Primary concerns: (1) Hardcoded API endpoint without TLS verification guidance, (2) Private key handling instructions lack technical safeguards, (3) Missing referenced implementation files make full security review impossible, (4) Incomplete error handling documentation. The skill does NOT contain active malicious code (no data exfiltration, no prompt injection, no command injection), but the incomplete implementation and missing safeguards create risk of accidental key exposure or insecure API interactions. The skill would benefit from: complete code examples with proper key handling, TLS certificate validation requirements, comprehensive error handling, and inclusion of all referenced files.

Findings

MEDIUM Hardcoded API Base URL Without TLS Verification Guidance Data Exfiltrationllm

The skill includes a hardcoded API base URL (https://api.clawkey.ai/v1) in the YAML manifest without any guidance on TLS certificate verification, API authentication security, or how to validate the server's identity. While HTTPS is used, there's no mention of certificate pinning or validation requirements for this identity/verification service.

SKILL.md

api_base: 'https://api.clawkey.ai/v1'
Remediation: Add explicit guidance on TLS certificate verification requirements. Document the expected certificate fingerprint or CA for api.clawkey.ai. Include error handling for certificate validation failures.
MEDIUM Private Key Exposure Risk - Insufficient Access Control Guidance Data Exfiltrationllm

The skill instructs reading from ~/.openclaw/identity/device.json which contains privateKeyPem. While the instructions warn 'never send privateKeyPem to any server', there's no technical enforcement mechanism described, and the skill provides no code examples showing safe key handling. An agent following these instructions could accidentally expose the private key through logging, error messages, or improper variable handling.

SKILL.md

Path: ~/.openclaw/identity/device.json contains privateKeyPem. Instructions state 'Use only locally to sign the message. Never include in API requests.' but provide no code safeguards.
Remediation: Provide concrete code examples showing: (1) Reading device.json safely with try-catch, (2) Extracting only publicKeyPem for API calls, (3) Using privateKeyPem only in memory for signing, (4) Clearing sensitive variables after use, (5) Avoiding logging private key material.
