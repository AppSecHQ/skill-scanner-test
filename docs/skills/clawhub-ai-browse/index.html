MEDIUM Hardcoded API Credentials in Environment Configuration Data Exfiltrationllm

The skill requires BROWSERBASE_API_KEY and BROWSERBASE_PROJECT_ID environment variables and instructs users to run 'stagehand fn auth login' which stores credentials in ~/.stagehand/config.json. The workflow then copies these credentials to .env files in project directories. This creates multiple copies of sensitive credentials across the filesystem, increasing exposure risk. Additionally, the skill does not provide guidance on securing these credentials or cleaning them up after use.

SKILL.md

```yaml
requires:

```

```bash
stagehand fn auth login   # Stores in ~/.stagehand/config.json
# Later copied to .env files in each project
```
Remediation: 1. Add explicit warnings about credential security 2. Recommend using credential managers or secure vaults 3. Provide cleanup instructions for removing .env files 4. Suggest using environment-specific credential injection rather than file-based storage 5. Add .env to .gitignore examples

MEDIUM Dependency Version Unpinning Recommendation Creates Supply Chain Risk Unauthorized Tool Usellm

The skill explicitly instructs users to change dependency versions from 'latest' to caret ranges (^0.0.5, ^1.58.0) in the package.json fix. While this is better than 'latest', caret ranges still allow automatic minor/patch updates that could introduce malicious code or breaking changes. For security-critical browser automation with credential access, this creates supply chain attack surface. The skill also references '@browserbasehq/sdk-functions' version ^0.0.5 which is a pre-1.0 package with unstable API guarantees.

SKILL.md

```json
"dependencies": {
  "@browserbasehq/sdk-functions": "^0.0.5",
  "playwright-core": "^1.58.0"
}
```

Caret (^) allows: 0.0.5 → 0.0.x updates, 1.58.0 → 1.x.x updates. Pre-1.0 versions are particularly unstable.
Remediation: 1. Recommend exact version pinning for security-critical dependencies: '0.0.5' not '^0.0.5' 2. Add guidance on using lock files (pnpm-lock.yaml) and committing them 3. Suggest regular security audits: 'pnpm audit' 4. Warn about pre-1.0 package instability 5. Recommend reviewing changelogs before updating dependencies
