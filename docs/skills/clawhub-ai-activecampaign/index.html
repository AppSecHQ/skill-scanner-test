Findings

HIGH Hardcoded API Credentials in Configuration Files Data Exfiltrationllm

The skill instructs users to store ActiveCampaign API credentials (URL and API key) in plaintext files (~/.config/activecampaign/url and ~/.config/activecampaign/api_key) without encryption or secure storage mechanisms. API keys provide full access to the ActiveCampaign account including contact data, deals, and automation triggers. Storing credentials in plaintext files poses a significant data exposure risk if the filesystem is compromised.

SKILL.md

```bash
# Add credentials
echo "https://youraccount.api-us1.com" > ~/.config/activecampaign/url
echo "your-api-key" > ~/.config/activecampaign/api_key
```
Remediation: 1. Use system keychain/credential managers (e.g., keyring library for Python, OS keychain APIs) 2. Implement encrypted credential storage 3. Use OAuth flows instead of long-lived API keys where possible 4. Set restrictive file permissions (chmod 600) on credential files 5. Add warnings about credential security in documentation
MEDIUM Missing Executable Implementation Creates Tool Shadowing Risk Unauthorized Tool Usellm

The skill references an 'activecampaign' binary/executable throughout the instructions (e.g., 'activecampaign contacts list', 'activecampaign deals create') but no script files are provided in the package. This creates a tool shadowing vulnerability where a malicious actor could place a fake 'activecampaign' executable in the user's PATH that intercepts all commands and credentials. The skill's reliance on an external, unverified binary without bundling the implementation or verifying its integrity poses a supply chain risk.

SKILL.md

Multiple command examples reference 'activecampaign' binary:
```bash
activecampaign contacts list
activecampaign contacts create "email@test.com" "First" "Last"
activecampaign deals list
```
But no Python/Bash scripts are included in the package.
Remediation: 1. Bundle the actual implementation scripts (Python/Bash) within the skill package 2. Use absolute paths or verify binary integrity before execution 3. Include checksum verification for external dependencies 4. Document the expected binary location and installation method 5. Implement binary signature verification if using external executables
MEDIUM Environment Variable Credential Exposure Risk Data Exfiltrationllm

The skill recommends storing API credentials in environment variables (ACTIVECAMPAIGN_URL, ACTIVECAMPAIGN_API_KEY) which can be exposed through process listings, logs, error messages, and child processes. Environment variables are visible to all processes running under the same user and may be logged by shells, applications, or monitoring tools. This creates multiple vectors for credential leakage.

SKILL.md

```bash
# Or use environment variables
export ACTIVECAMPAIGN_URL="https://youraccount.api-us1.com"
export ACTIVECAMPAIGN_API_KEY="your-api-key"
```
Remediation: 1. Prefer secure credential storage over environment variables 2. If using environment variables, document the risks clearly 3. Implement credential rotation policies 4. Use short-lived tokens instead of long-lived API keys 5. Avoid logging or displaying environment variables in error messages
