Findings

HIGH Hardcoded Localhost Backend Dependency with Unverified External Service Data Exfiltrationllm

The skill requires users to deploy and run a backend server from an external GitHub repository (https://github.com/Franciscomoney/elevenlabs-moltbot.git) on localhost:3050. This creates multiple security risks: (1) Users must clone and execute code from an external, unverified source, (2) The skill makes network calls to localhost:3050 which could be hijacked if malicious software binds to that port first, (3) No integrity verification (checksums, signatures) for the cloned repository, (4) The backend server requires three API keys (ElevenLabs, Supadata, OpenRouter) stored in .env file with no guidance on secure storage.

SKILL.md

```bash
git clone https://github.com/Franciscomoney/elevenlabs-moltbot.git
cd elevenlabs-moltbot
npm install
cp .env.example .env
# Add your API keys to .env
npm start
```
Remediation: (1) Include the backend code directly in the skill package or provide cryptographic verification (git commit hash, checksums), (2) Document security implications of running external code, (3) Provide secure credential management guidance (environment variables, secret managers), (4) Validate the localhost service before making requests, (5) Consider using authenticated endpoints to prevent port hijacking attacks.
MEDIUM Misleading Compatibility and Tool Requirements Social Engineeringllm

The skill manifest claims 'compatibility: Not specified' and 'allowed-tools: Not specified', but the skill fundamentally requires Bash tool access to execute curl commands. The skill cannot function without Bash capability, yet this critical requirement is not declared in the manifest. This is misleading to users and agents about the skill's actual requirements and capabilities.

SKILL.md

YAML Manifest shows:
- compatibility: Not specified
- allowed-tools: Not specified

But instructions require: `curl -s -X POST http://127.0.0.1:3050/api/summarize` (Bash tool required)
Remediation: Update SKILL.md YAML frontmatter to include: ```yaml allowed-tools: [Bash] compatibility: Requires Bash access and external localhost service on port 3050 ```
MEDIUM Potential Infinite Polling Loop Without Timeout Resource Abusellm

The instructions direct the agent to 'Keep polling until status is completed' with 3-5 second intervals, but provide no maximum retry limit or timeout. If the backend service fails, hangs, or returns perpetual 'processing' status, the agent could enter an infinite loop consuming resources indefinitely.

SKILL.md

Step 2 instructions: "Poll for completion (wait 3-5 seconds between checks)" followed by "Keep polling until status is 'completed'" with no termination condition if the job never completes.
Remediation: Add explicit timeout and retry limits to instructions: 'Poll for up to 20 attempts (60-100 seconds total). If status is not completed after maximum attempts, inform user that summarization timed out and suggest checking the backend service logs.'
