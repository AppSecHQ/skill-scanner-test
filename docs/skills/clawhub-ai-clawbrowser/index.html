The clawbrowser skill is a legitimate browser automation tool using Playwright CLI with MODERATE security concerns. The primary issues are: (1) overly permissive wildcard tool restrictions that could be tightened, (2) missing metadata reducing transparency, (3) incomplete documentation with truncated instructions and missing referenced files, and (4) lack of resource management guidance for persistent sessions. The skill performs its stated function of browser automation but would benefit from stricter tool permissions, complete documentation, and resource management guidelines.

What this skill does

Use when the agent needs to drive a browser through the Microsoft Playwright CLI (`playwright-cli`) for navigation, form interactions, screenshots, recordings, data extraction, session management, or debugging without loading a full MCP browser. It trains the agent on the CLI commands, snapshots, and session/config habits that make Playwright CLI reliable for scripted browsing.

Findings

MEDIUM Overly Permissive Tool Restriction Pattern Unauthorized Tool Usellm

The allowed-tools field uses a wildcard pattern 'Bash(playwright-cli:*)' which permits execution of ANY command starting with 'playwright-cli'. This broad permission could be exploited if an attacker can influence command arguments or if the playwright-cli tool itself has vulnerabilities. The wildcard pattern defeats the purpose of granular tool restrictions.

SKILL.md

allowed-tools: Bash(playwright-cli:*)
Remediation: Replace the wildcard pattern with explicit allowed commands (e.g., 'Bash(playwright-cli open)', 'Bash(playwright-cli snapshot)', 'Bash(playwright-cli click)'). If wildcards are necessary, document the security implications and ensure input validation occurs before command execution.
MEDIUM Potential for Unbounded Browser Sessions Resource Abusellm

The skill encourages persistent browser sessions with cookies and storage but provides no guidance on session cleanup, timeout limits, or resource management. The instructions mention 'session-stop-all' and 'session-delete' but don't enforce or recommend regular cleanup. Accumulated sessions could lead to resource exhaustion.

SKILL.md

Use --session=<name> to keep cookies, storage, and tabs isolated per workflow. Sessions behave like persistent profiles: they remember auth state, history, and tabs between commands.
Remediation: Add explicit guidance on session lifecycle management: (1) Recommend session cleanup after workflows complete, (2) Document maximum recommended session count, (3) Suggest timeout policies for idle sessions, (4) Add example cleanup commands to workflow templates.
