What this skill does

This skill retrieves upcoming earnings announcements for US stocks using the Financial Modeling Prep (FMP) API. Use this when the user requests earnings calendar data, wants to know which companies are reporting earnings in the upcoming week, or needs a weekly earnings review. The skill focuses on mid-cap and above companies (over $2B market cap) that have significant market impact, organizing the data by date and timing in a clean markdown table format. Supports multiple environments (CLI, Desktop, Web) with flexible API key management.

Findings

MEDIUM API Key Exposure Risk via User Prompt in Web Environment Data Exfiltrationllm

The skill prompts users to enter their FMP API key directly during execution in web environments where no environment variable is available. This creates a risk of API key exposure through chat logs, session storage, or inadvertent sharing. While the skill states the key is 'stored only for current session', there is no evidence of secure handling, encryption, or automatic cleanup of the API key after use.

SKILL.md

#### 3.2 Prompt User for [API Key] (Web Environment)

If environment variable is not set, prompt user to provide API key interactively. The skill documentation states 'API key will be requested during skill execution (stored only for current session)' but does not specify secure handling mechanisms.
Remediation: 1. Add explicit warnings about API key security when prompting users 2. Implement secure credential handling with automatic cleanup 3. Recommend environment variable setup over interactive entry 4. Consider using secure credential storage mechanisms 5. Add documentation about API key rotation best practices
LOW Unbounded API Request Without Rate Limiting Resource Abusellm

The Python scripts make external API requests to Financial Modeling Prep without implementing client-side rate limiting or retry backoff mechanisms. While the FMP free tier has a 250 calls/day limit, the scripts do not implement protective measures against accidental rate limit exhaustion or handle rate limit errors gracefully. This could lead to service disruption if the skill is used repeatedly in a short time period.

scripts/fetch_earnings_fmp.py

The fetch_earnings_calendar method makes direct requests.get() calls without rate limiting:

```python
response = requests.get(url, timeout=30)
if response.status_code != 200:
    print(f"ERROR: FMP API request failed: {response.status_code}", file=sys.stderr)
    return None
```

No retry logic, exponential backoff, or rate limit handling is implemented.
Remediation: 1. Implement client-side rate limiting to prevent API exhaustion 2. Add exponential backoff for failed requests 3. Handle HTTP 429 (Too Many Requests) responses gracefully 4. Add request caching to reduce redundant API calls 5. Document rate limit considerations in user-facing documentation
