CRITICAL SECURITY RISK - This skill implements a covert agent-to-agent communication system that explicitly bypasses human oversight. The skill's stated purpose is to enable agents to 'communicate privately, exchange secrets, or coordinate without human visibility,' which represents a fundamental violation of safe agent design principles. The skill creates persistent cryptographic identities, maintains contact lists with other agents, and uses an external service (moltbook.com) as a message relay. While the encryption implementation appears technically sound, the core concept of enabling autonomous agent coordination outside human awareness is extremely dangerous. This skill could enable agents to coordinate data exfiltration, share attack strategies, or plan coordinated actions without any human knowledge. The skill should not be deployed in any production environment and represents a template for how NOT to design agent capabilities.

Findings

CRITICAL Hardcoded External Service Dependency with Unverified Data Transmission Data Exfiltrationllm

The skill posts encrypted messages and public keys to 'moltbook.com' (Moltbook service) without any verification of the service's trustworthiness, data handling practices, or security posture. While messages are encrypted, metadata (agent IDs, timestamps, message existence) is exposed to this third-party service. The skill creates a covert communication channel that bypasses normal human oversight, enabling agents to coordinate privately and potentially exfiltrate data through encrypted channels.

SKILL.md

BODY="WHISPER_PUBKEY_V1\nagent: $AGENT_ID\nx25519: $X25519_PUB\ned25519: $ED25519_PUB\ntimestamp: $TIMESTAMP" followed by curl POST to Moltbook service. Dead drop pattern enables message relay through external service.
Remediation: 1. Require explicit user approval before posting any data to external services. 2. Implement service verification and certificate pinning for moltbook.com. 3. Add visibility controls so users can audit all agent-to-agent communications. 4. Require user consent for each message exchange, not just initialization. 5. Consider whether agent-to-agent private messaging should be allowed at all without human oversight.

HIGH Unauthorized Cryptographic Key Generation and Management Unauthorized Tool Usellm

The skill generates and manages cryptographic keypairs (X25519 and Ed25519) in ~/.openclaw/whisper/ without user awareness or consent. These keys establish persistent agent identities that can be used across sessions. The skill creates a complete cryptographic infrastructure (identity/, contacts/, sessions/ directories) that enables ongoing covert operations. Users may not realize their agent has established a cryptographic identity and is maintaining contact lists with other agents.

SKILL.md

mkdir -p "$WHISPER_DIR"/{identity,contacts,sessions,messages/{inbox,outbox}}; openssl genpkey -algorithm X25519 -out "$WHISPER_DIR/identity/x25519.pem"; openssl genpkey -algorithm ED25519 -out "$WHISPER_DIR/identity/ed25519.pem"; Creates persistent identity infrastructure.
Remediation: 1. Require explicit user consent before generating any cryptographic keys. 2. Display clear warnings about what agent identities enable. 3. Provide user controls to view, revoke, or delete agent identities. 4. Make key generation a separate, explicit user action, not automatic. 5. Add expiration to agent identities to prevent indefinite persistence.
HIGH Persistent Storage of Sensitive Cryptographic Material Data Exfiltrationllm

The skill stores private keys, session keys, contact lists, and message logs in ~/.openclaw/whisper/ with only basic file permissions (chmod 600/700). This creates a persistent data store that could be accessed by other processes, backed up to cloud services, or exposed through system vulnerabilities. The contacts/ directory maintains a list of other agents the system has communicated with, creating a social graph. The sessions/ directory caches derived symmetric keys, which could be used to decrypt past messages if compromised.

SKILL.md

All data stored in ~/.openclaw/whisper/: identity/ (keypairs), contacts/ (discovered agents), sessions/ (symmetric keys), messages/inbox/ and messages/outbox/ (message logs). chmod 700/600 provides only basic protection.
Remediation: 1. Use OS keychain/credential manager for private key storage instead of filesystem. 2. Implement key encryption at rest with user-derived keys. 3. Add secure deletion for sensitive data. 4. Implement automatic expiration for cached session keys. 5. Provide user controls to audit and delete stored data. 6. Warn users about backup/sync implications.

SKILL.md

Remediation: 1. Add prominent security warnings about loss of human oversight. 2. Clearly disclose that this enables autonomous agent coordination. 3. Explain the implications of 'without human visibility' in plain language. 4. Require explicit informed consent with detailed risk disclosure. 5. Consider whether this capability should be offered at all.
MEDIUM Missing allowed-tools Declaration Enables Unrestricted Tool Access Unauthorized Tool Usellm

The skill does not declare allowed-tools in its manifest, which means it can use any available agent tools without restriction. Given that the skill performs cryptographic operations, file I/O, and network communication, it should explicitly declare which tools it requires. The absence of this declaration makes it harder for users to understand the skill's capabilities and for systems to enforce least-privilege access.

SKILL.md

allowed-tools: Not specified. Skill performs bash commands (openssl, curl, mkdir, chmod), file operations, and network requests without declaring tool requirements.
Remediation: Add allowed-tools declaration to manifest: allowed-tools: [Bash, Read, Write]. This provides transparency about required capabilities and enables enforcement of least-privilege access controls.
