CRITICAL Arbitrary Remote Code Execution via Unverified Script Download Command Injectionllm

The installation instructions direct users to download and execute a bash script from GitHub without any integrity verification (no checksum, signature, or hash validation). The script is immediately made executable and placed in a system directory (/usr/local/bin/). An attacker who compromises the GitHub repository or performs a man-in-the-middle attack could inject malicious code that would be executed with the user's privileges. This represents arbitrary code execution with no security controls.

SKILL.md

curl -fsSL https://raw.githubusercontent.com/adinvadim/2captcha-cli/main/solve-captcha \
  -o /usr/local/bin/solve-captcha && chmod +x /usr/local/bin/solve-captcha
Remediation: 1. Provide SHA256 checksums for the script and verify after download. 2. Use signed releases with GPG verification. 3. Host the tool in a package manager (apt, brew, pip) with built-in integrity checks. 4. Warn users about the security implications of executing remote scripts. 5. Consider bundling the script within the skill package instead of downloading from external sources.
HIGH Hardcoded API Key Storage in Plaintext Configuration File Data Exfiltrationllm

The skill instructs users to store their 2Captcha API key in plaintext in ~/.config/2captcha/api-key without any encryption or access controls. API keys are sensitive credentials that provide access to paid services and should be protected. Storing them in plaintext makes them vulnerable to theft by malware, other users on shared systems, or accidental exposure through backups/logs. The skill also suggests using environment variables, but the primary instruction is plaintext file storage.

SKILL.md

mkdir -p ~/.config/2captcha
echo "YOUR_API_KEY" > ~/.config/2captcha/api-key
Remediation: 1. Use system keychain/credential managers (macOS Keychain, Windows Credential Manager, Linux Secret Service). 2. Encrypt the API key file with user-specific encryption. 3. Set restrictive file permissions (chmod 600). 4. Prefer environment variables over file storage. 5. Warn users about the security implications of plaintext credential storage. 6. Consider using the agent's secure credential storage if available.
HIGH Facilitation of CAPTCHA Bypass for Potentially Malicious Automation Social Engineeringllm

The skill's stated purpose is to 'bypass captchas during web automation, account creation, or form submission.' CAPTCHAs exist as security controls to prevent automated abuse, bot attacks, spam, and fraudulent account creation. This skill explicitly facilitates circumventing these security measures. While there may be legitimate accessibility or testing use cases, the skill provides no ethical guidelines, warnings about terms of service violations, or restrictions on use. The workflow section specifically describes browser automation to inject CAPTCHA tokens, which is commonly used for malicious purposes including credential stuffing, spam, scraping protected content, and mass account creation for fraud.

SKILL.md

Description: Solve CAPTCHAs using 2Captcha service via CLI. Use for bypassing captchas during web automation, account creation, or form submission.

Workflow for Browser Automation section describes injecting tokens to bypass security controls.
Remediation: 1. Add prominent warnings about legal and ethical implications. 2. Include terms of service compliance requirements. 3. Restrict use cases to legitimate purposes (accessibility, authorized testing). 4. Add ethical guidelines and responsible use policy. 5. Warn about potential account bans and legal consequences. 6. Consider whether this skill should be distributed at all given its primary use case for circumventing security controls.
