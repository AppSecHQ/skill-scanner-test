The health-tracker skill presents MEDIUM security risk primarily due to unbounded autonomous behavior (auto-logging without consent) and missing tool declarations. The skill's core functionality (tracking water intake and sleep) is legitimate, but implementation choices create autonomy and transparency concerns. The auto-log feature that writes data without user interaction after 15 minutes represents an availability disruption pattern. With remediation of the auto-log behavior and addition of proper tool declarations, this skill could be considered safe for use.

Findings

MEDIUM Unbounded Autonomy with Auto-Logging Without User Consent Resource Abusellm

The skill implements an 'auto-log' feature that automatically records water intake entries (with 0 cups) if the user does not respond within 15 minutes of a reminder. This creates an unbounded autonomous behavior where the system makes decisions and modifies user data without explicit consent. The auto-log entries are marked as automatic but still pollute the user's health tracking data, potentially affecting statistics and habit calculations. This represents a form of availability disruption through unwanted automated actions.

SKILL.md

Auto-log section states: 'Nếu không trả lời sau 15 phút → Tự động ghi: {cups: 0, auto: true, note: "Tự động ghi nhận - không phản hồi"}'. This means the system will continuously create entries without user interaction.
Remediation: Remove the auto-log feature or require explicit user opt-in with clear warnings. If retained, implement: (1) User confirmation before enabling auto-log, (2) Maximum limit on consecutive auto-logs, (3) Clear visual distinction in statistics between real and auto-logged entries, (4) Easy way to disable the feature, (5) Option to bulk-delete auto-logged entries.

SKILL.md

LOW Undeclared Tool Usage and Missing Tool Restrictions Unauthorized Tool Usellm

The skill declares three tools (log_water, log_sleep, view_stats) in its documentation but does not specify 'allowed-tools' in the YAML manifest. While this field is optional, the skill's behavior suggests it needs Write access (to modify health-data.json) and potentially Bash/Python (for node-cron scheduling). The absence of declared tool restrictions means the skill could potentially use any available agent tools without user awareness, creating a tool exploitation risk.

SKILL.md

YAML manifest shows 'allowed-tools: Not specified' but the skill clearly requires file write operations ('Lưu tại: ./health-data.json') and mentions npm package installation ('npm install node-cron'). The tools section describes data persistence but doesn't declare which agent tools are needed.
Remediation: Add 'allowed-tools' field to YAML manifest specifying exactly which tools are required (e.g., [Write, Read] for data persistence). If scheduling requires Bash/Python execution, declare those explicitly. This provides transparency and allows users to understand the skill's capabilities before activation.
LOW Missing Provenance and Security Metadata Data Exfiltrationllm

The skill's YAML manifest lacks critical security metadata including license information and compatibility declarations. While 'author' is specified as 'Your Name' (a placeholder), there is no license field to indicate usage rights and liability. The absence of compatibility information means users cannot assess whether the skill is safe for their environment (Claude.ai, Claude Code, API). This represents a minor information disclosure issue affecting user decision-making.

SKILL.md

YAML shows: 'license: Not specified', 'compatibility: Not specified', 'author: Your Name' (placeholder value). Only version (1.0.0) and tags are provided.
Remediation: Add complete metadata: (1) Specify a valid license (MIT, Apache-2.0, etc.), (2) Declare compatibility environments, (3) Replace placeholder author with real identity or organization, (4) Consider adding repository URL for transparency and updates.
LOW External Dependency Without Version Pinning Resource Abusellm

The skill requires 'node-cron' npm package for scheduling functionality but does not specify a version constraint. This creates a supply chain risk where future versions could introduce breaking changes, vulnerabilities, or malicious code. While not immediately exploitable, unpinned dependencies are a security best practice violation that could lead to availability issues or unexpected behavior.

SKILL.md

Installation instructions show: 'npm install node-cron' without version specification (e.g., 'node-cron@^3.0.0' or 'node-cron@3.0.2').
Remediation: Pin the node-cron dependency to a specific version or version range: 'npm install node-cron@^3.0.0'. Document the tested version in the README. Consider adding a package.json file to the skill package with locked dependencies.
